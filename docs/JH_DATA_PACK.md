# JH Hedge Fund Data Pack V1

호행처럼 관리자 안에서 공식 FRED 지표 40개를 수집하고, 기간별 변화와 이상신호를 계산해 `COPY FOR GPT` 형식으로 제공한다.

## 데이터 흐름

1. Vercel Cron이 매일 `GET /api/cron/fred`를 호출한다.
2. 서버 전용 수집기가 FRED `series.last_updated`를 먼저 확인한다.
3. 원천 갱신시각과 최신 관측일이 이전 실행과 같으면 관측값 다운로드와 DB 쓰기를 건너뛴다.
4. 바뀐 지표만 와이프 계정의 별도 Supabase `historical_data`에 `(series_id, observed_at)` 기준으로 upsert한다.
5. 월간·분기 지표는 연결된 FRED 발표정보와 다음 발표일도 함께 확인한다.
6. `/admin/jh-market`이 원본 시계열에서 변화율, 백분위, Z-Score, 추세, 이상신호와 중요도를 계산한다.
7. 수집 시점의 계산 결과와 COPY Pack을 해당 `collection_runs.metadata`에 일별 아카이브로 보관한다.
8. 관리자는 과거 날짜를 선택하거나 `최신화 후 COPY` 버튼으로 구조화된 Morning Meeting Pack을 복사한다.

기존 호행처럼 콘텐츠 Supabase와 JH 데이터 Supabase는 서로 분리한다. JH 비밀키는 서버 전용 코드에서만 사용하며 브라우저 번들에는 포함하지 않는다.

## 환경변수

Vercel 프로젝트에 다음 값이 필요하다.

- `JH_SUPABASE_URL`
- `JH_SUPABASE_SECRET_KEY`
- `FRED_API_KEY`
- `CRON_SECRET`
- 기존 관리자 인증용 `NEXT_PUBLIC_SUPABASE_URL`
- 기존 관리자 인증용 `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`

## 자동수집

`vercel.json`의 `30 23 * * *`는 UTC 기준이며 한국시간으로 다음 날 오전 8시 30분이다. `CRON_SECRET`이 설정되면 Vercel이 자동 호출에 `Authorization: Bearer ...` 헤더를 붙인다.

수집 모드:

- `auto`: 해당 지표의 계산용 이력이 부족하면 과거 구간 적재, 충분하면 최근 구간 갱신
- `backfill`: 모든 활성 지표의 과거 구간 재확인
- `daily`: 모든 활성 지표의 최근 구간만 갱신

관리자 화면의 `지금 데이터 수집`은 `auto`를 사용한다. 일부 지표가 실패하거나 이력이 덜 채워져도 다음 실행에서 해당 지표만 다시 과거 적재한다.

현재 날짜의 `최신화 후 COPY`는 마지막 FRED 원천 확인이 30분을 넘겼을 때 자동으로 증분 수집을 먼저 실행한다. 원천 갱신시각이 같은 지표는 다시 저장하지 않기 때문에 최초 적재 이후의 실행은 가볍다. 과거 아카이브를 복사할 때는 현재 데이터로 바꾸지 않고 선택한 당시 스냅샷을 그대로 복사한다.

성공한 과거 적재 기록은 다음 실행의 이력 완성 여부 판단에 재사용한다. 또한 수집 직후 일별 아카이브를 만들 때 계산한 대시보드를 관리자 화면 응답에도 함께 사용해, 동일한 40개 지표 분석을 연속 두 번 실행하지 않는다.

Vercel Hobby의 Cron은 하루 1회 실행 제한이 있으므로 예약 실행은 오전 8시 30분 한 번을 유지한다. 실제 GPT 분석 직전 최신성은 `최신화 후 COPY`의 온디맨드 증분 확인으로 보완한다.

## 분석 규칙

- 일간: 1D / 5D / 20D / 60D
- 주간: 1W / 4W / 13W / 52W
- 월간: 1M / 3M / 6M / 12M
- 분기: 1Q / 2Q / 4Q / 8Q
- 백분위와 Z-Score는 지표 빈도에 맞는 과거 관측 구간으로 계산한다.
- 금리·신용의 변화는 bp, 물가 YoY와 GDP 연율의 변화는 pp로 표시한다.
- Importance Score는 변화 크기 30%, 역사적 극단 25%, 교차자산 확인 20%, 추세 영향 15%, 지속성 10%를 사용한다.
- 관측일은 그 수치가 대표하는 기간이며 수집일 또는 발표일과 다를 수 있다.
- `원천 최신`: FRED의 `last_updated`까지 확인된 최신 유효값
- `발표 대기`: 월간·분기 지표의 공식 최신값이며 다음 발표를 기다리는 상태
- `확인 필요`: 원천 갱신시각과 관측일이 모두 해당 발표주기의 허용범위를 넘긴 상태
- 오래된 값은 0으로 바꾸지 않고 실제 관측일, FRED 원천 갱신시각, 다음 발표일을 함께 표시한다.
- COPY Pack은 `FRESH`와 `AWAITING_RELEASE`만 공식 최신값으로 사용하고 `DELAYED`와 `UNAVAILABLE`은 당일 방향성 근거에서 제외하도록 GPT에 명시한다.

## 보안

- Cron API는 `CRON_SECRET`으로 보호한다.
- 관리자 데이터 API는 기존 호행처럼 Supabase 로그인 토큰을 Auth 서버에서 다시 검증한다.
- `JH_SUPABASE_SECRET_KEY`와 `FRED_API_KEY`는 클라이언트에 전달하지 않는다.
- 관리자 화면이 보내는 응답은 표시에 필요한 지표와 계산 결과만 포함한다.

## 운영 확인

1. `/admin` 로그인
2. `JH 투자 레이더` 선택
3. 최초 한 번 `지금 데이터 수집` 실행
4. 공식 최신 상태와 최근 FRED 원천 확인 `정상 완료` 확인
5. `최신화 후 COPY` 실행

일부 FRED 시리즈가 일시적으로 응답하지 않으면 전체 화면을 막지 않고 성공 지표만 보여주며, 실패 수를 커버리지와 최근 실행 기록에 표시한다.
